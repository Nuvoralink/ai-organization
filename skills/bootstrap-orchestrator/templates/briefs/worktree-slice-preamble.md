# Worktree slice preamble (prepend to the dispatch brief when the slice runs in a worktree)

You are working in the git worktree at **`<WORKTREE_ABS_PATH>`** on branch **`<BRANCH>`**. The session cwd is the MAIN checkout, NOT your worktree — two same-named trees exist and nothing mechanical forces an edit to the right one.

0. **Make the worktree buildable BEFORE any check — a fresh worktree has NO gitignored artifacts.** A linked worktree shares tracked files but NOT gitignored ones (`node_modules`, built `dist`, the generated ORM client, `.env`, husky's `_/` dir). Until you create them, builds resolve the MAIN checkout's STALE copies (the worktree false-red / false-green — an already-correct base branch looks broken) or fail on missing config. Run the repo's setup in the worktree: **`npm install`** (so internal `file:`/`workspace:` packages resolve IN-TREE, not to the main checkout — the `check-shared-resolution` gate asserts this); **regenerate codegen** (`prisma generate` etc. — `prisma generate` needs a RESOLVABLE `DATABASE_URL`, but a dummy `postgresql://…` suffices because it reads the schema, not the DB); **provide `.env`** (copy the main checkout's, or a minimal dummy for build/typecheck); and **run the hook installer** (`npx husky` / the `prepare` script — a worktree runs ZERO hooks until it is re-run). Only then run checks. The build's `check-shared-resolution` step will fail fast with the fix if an internal package still resolves to a foreign tree.
1. **Every Edit/Write uses the WORKTREE's absolute path** (`<WORKTREE_ABS_PATH>/...`), never the main checkout's. A main-checkout path silently edits the wrong tree (which may hold another agent's uncommitted work).
2. **Before running ANY check**, confirm your edits landed in the worktree: `git -C <WORKTREE_ABS_PATH> status --short` must show exactly the files you expected dirty. **An empty worktree diff after edits means the edits went to the wrong tree** — STOP, recover with a patch-scoped apply + a path-limited `git checkout -- <files>` in the main checkout (never a blanket reset), and re-edit in the worktree.
3. **Run checks with the worktree cwd:** `cd <WORKTREE_ABS_PATH> && npm run <check>; echo "EXIT: $?"` — read the sentinel exit, not a piped tail.
4. **You do NOT commit/merge** unless the brief says so — produce your files; the orchestrator commits (an implementer that finishes uncommitted through a worktree is expected; the orchestrator commits before dispatching any tree-touching reviewer, since a reviewer with Bash can `git checkout` away uncommitted work — PR #152).
5. **Reviewer/auditor lenses NEVER mutate the tree** — no `git checkout <file>`, `git stash`, branch switch, or `git reset`. To evaluate a mutation, READ and reason; describe it for the orchestrator to run.
