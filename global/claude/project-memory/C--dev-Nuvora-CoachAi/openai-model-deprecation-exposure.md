## Bug surfaced by the eval — reasoning_effort enum churn (FIXED, PR #93)
OpenAI revised the gpt-5-family `reasoning_effort` enum to **`none`|`low`|`medium`|`high`|`xhigh`** (dropped `minimal`, added `none`/`xhigh`). The gateway (`aiOpenAiGateway.ts`) hardcoded `reasoning_effort='minimal'` for every reasoning-model `json_object` call → the **current `gpt-5-mini-2025-08-07` snapshot 400s on it** → the **whole mini-fleet was silently 400ing** (try/caught → degraded scores/coaching, no crash). **Fix: `'minimal'`→`'low'`** (valid across BOTH the old and new enums — the safe cross-version floor). NOT a live firefight (≈0 prod analyses per [[gtm-readiness-threshold]]; 0 Sentry hits over 30d), but it would degrade every analysis once real calls flow. **Lesson:** a hardcoded provider-API enum value is deprecation-fragile, and because the stage degrades silently, *monitoring won't catch it — an eval did.* Prefer cross-version-safe param values.

## Price correction (FIXED, PR #92)
The builtin price floor booked **gpt-5-mini at $0.125/$1.00 — exactly half** the standard $0.25/$2.00 (a stale openrouter/flex figure). Prod price DBs are empty + env omits gpt-5-mini → the floor is authoritative → the mini-fleet was **under-metered ~2×** (skewed Coach+ seat COGS). ## Cutover eval (gpt-5-mini → gpt-5.4-mini) — VERDICT: NOT a clean drop-in for the SCORE path
Two harnesses (internal eval DB; identical prompt both arms, model the only variable; cost from the corrected table):
- **`backend/scripts/miniFleetModelEval.ts`** (general semantic prompt — call-type + coaching moments): 20 sessions → **100% agreement** (13 shared keys), ~1.9× cost (+$2.62/1k). Swap proven (echoed `gpt-5-mini-2025-08-07` vs `gpt-5.4-mini-2026-03-17`). The general surface is fine.
- **`backend/scripts/miniFleetChecklistEval.ts`** (the SCORE-bearing batched checklist adjudication — `buildChecklistBatchPrompt`/`chunkRequiredRows`, all 4 AI modes `on`; has `--arm-a`/`--arm-b` flags + 3 behavior-neutral lib `export` additions in semanticJudgment.ts): 8 sessions → **gpt-5-mini vs gpt-5.4-mini = 61.8% verdict agreement (66/173 disagree, 38%)**, vs the **same-model noise floor gpt-5-mini-vs-gpt-5-mini = 86.7% (24/180, 13%)**. So gpt-5.4-mini diverges **~3× the noise floor** — ~25 pts of REAL model divergence (whole sections flipping to `not_applicable`, met↔unmet flips). **A blind env-flip would shift scores.** Checklist-path cost +$13.58/1k (gpt-5.4-mini ~$0.037 vs gpt-5-mini ~$0.023/analysis).
- **BLIND-JUDGE VALIDATION (the divergence is a REGRESSION, not noise and not an upgrade):** ran `--judge` (an independent **claude-sonnet-4-6** judge, model identities blinded, grounded in the per-item transcript window, decides which verdict the transcript supports). Of 63 disagreements: **gpt-5-mini more-correct 42, gpt-5.4-mini 12, both-wrong 9 → 78% vs 22% decisive.** Pattern: **gpt-5.4-mini is systematically TOO LENIENT** — hands out yes/partial credit the rep didn't earn (no specific value, didn't restate purpose, rushed/lost control, no clean ending), where gpt-5-mini's stricter "no" matches the transcript. For a coaching product a lenient checklist judge = **inflated scores** = worse coaching. (Amin's hypothesis "maybe 5.4 judges better" was checked + refuted; my own worst-session hand-read had over-indexed on one debatable not_applicable-applicability case — the aggregate refutes it. Judge is NOT merely N/A-biased: it reasons applicability case-by-case + flags both-wrong with the correct third verdict; spot-checked accurate against the b82cb18f transcript.) Caveat: one strong LLM referee, not ground truth — a 2nd judge (gpt-5.5) would make it bulletproof.
- **DEADLINE Dec 11, 2026** (~6mo). Do NOT flip the checklist path to gpt-5.4-mini as-is. Options: (1) **try gpt-5.4 (full)** via `--arm-b gpt-5.4` + `--judge` (~$3) — a bigger model may not have the leniency drift; (2) tune a gpt-5.4-mini checklist prompt adapter to tighten it + re-eval to ≈ the noise floor; (3) re-baseline scores (riskiest). The harness `--judge` mode (blind Sonnet referee + `--arm-a/--arm-b`) is the reusable tool for every future model-cutover quality call.
- **Side-finding:** the checklist stage is ~13% noisy WITH ITSELF (86.7% self-agreement) — reasoning-model run-to-run verdict variance → inherent score wobble independent of any cutover; worth a score-trust look.
