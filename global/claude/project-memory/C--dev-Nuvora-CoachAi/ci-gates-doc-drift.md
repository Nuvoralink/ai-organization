**MERGE-GATE RECALIBRATION (2026-07-11, Amin's directive):** GitHub Actions is **billing-blocked** — workflow jobs fail in 2-4 seconds at setup across unrelated commits (infra, NOT code; the cue: read failure DURATION + the HEAD commit message before treating red CI as a blocker). The interim merge gate is **`npm run ci:local`** (`scripts/ci-local.mjs`, added 67b9a766): a step-for-step, env-for-env mirror of `.github/workflows/ui-source-of-truth-gates.yml` (the `gates` job) + `backend-db-regressions.yml` (`dialer-db-regressions`), streaming output with REAL exit codes (no piped-tail masking) and a per-step PASS/FAIL summary. Flags: `--gates-only` (sufficient for a frontend-only diff); the DB job runs only when `CI_LOCAL_DB_URL` points at a disposable localhost Postgres, else it **skips LOUDLY** (a backend slice touching dialer scope must provide the DB before merge). Keep ci-local.mjs in lockstep with the two workflows — drift = false local green. **Run `npm run ci:local` before every PR** (it supersedes bare `npm run verify` as the pre-PR mirror; verify remains a subset). While Actions is down, `release-verifier` post-merge is mandatory-blocking, not advisory. Restoring Actions billing (or a self-hosted runner) is an open ops item with Amin.

The GitHub **"UI source-of-truth gates"** CI job (`.github/workflows/ui-source-of-truth-gates.yml`, one `gates` job) runs, in order: `npm run check:ui`, `check:ui-continuity`, `lint:typography --workspace=frontend`, **`npm run test:doc-code-drift`** (`scripts/check-doc-code-drift.mjs`), **`npm run test --workspace=frontend`** (frontend vitest — 62 files/316 tests; added 2026-06-22 because the suite was never in CI and 2 `TeamManagementPage` MGR-8 tests rotted red on `main` unnoticed), then `prisma generate` + `check:script-imports`. Only `check:ui` + `check:ui-continuity` are wired into the PostToolUse edit hook; **`test:doc-code-drift`, frontend vitest, and `check:script-imports` are NOT** — they run only in CI, so an edit can pass the hook + local check:ui yet still fail the CI gates job. Run `npm run test --workspace=frontend` (or all gate steps) locally before pushing.

`test:doc-code-drift` AUTO-DISCOVERS every non-test `.ts/.tsx` under these dirs as a frontend authority consumer and fails (`DCD-AUTHORITY-MANIFEST-1`) until each is classified in `docs/app-plan/v2-authority-source-inventory.json` → `frontendAuthorityConsumers` (value `"migrate"`): `frontend/src/components/coaching/callReview/v2/`, `frontend/src/pages/`, `frontend/src/components/dashboard/tabs/`, `frontend/src/components/dashboard/myCoaching/`. It likewise discovers backend routes, prisma models, shared `*Authority*`/`*Analytics*` exports, and scripts/rules (see `discoverAuthoritySurfaces()`). It also flags STALE entries (`MANIFEST-3`) — so on DELETE, remove the inventory line too.

**How to apply:** when ADDING or REMOVING a file in those dirs, add/remove its inventory entry in `v2-authority-source-inventory.json` in the same change, and run `npm run test:doc-code-drift` locally before pushing — don't rely on the edit hook. The human `docs/app-plan/v2-authority-migration-inventory.md` table is category-level (e.g. one "Call Review v2" row) and usually needs no per-file row. Bit the 2026-06-15 off-script feature: a new `OffScriptSection.tsx` passed the hook + local check:ui but failed the CI gates job until classified `"migrate"`. Lesson: run all three gate steps locally before opening a PR. See [[agent-fleet-setup]].

**Two CI footguns (2026-06-23, the Collective-Learning + notifications-tab sprint):**
1. The **frontend vitest gate can print `Test Files NN passed` yet exit 1** — that's an **Unhandled Error** caught after the run (vitest summary: `Errors 1 error`), NOT a failed assertion. **FIXED 2026-06-23 in PR #113** (`b1357996`), but the mechanism recurs so keep it in mind: the real error was `EnvironmentTeardownError: Closing rpc while "onUserConsoleLog" was pending` originating in `DashboardPage.test.tsx`. Root cause was NOT unawaited fetch mocks (those `manager_notifications_fetch_failed` / `recent_sessions_fetch_failed` lines are CAUGHT — benign; don't be misled by the event NAMES containing "failed"). It was a **console-flood vs worker-teardown race**: `logClientDiagnostic()` (`frontend/src/lib/clientDiagnostics.ts:142`) `console.warn`s every diagnostic when `import.meta.env.DEV` (which vitest runs as); DashboardPage mounts components whose gracefully-failing unmocked fetches each log one → a flood of console RPCs → on a slow CI runner one is still pending at teardown → unhandled error → exit 1. **Fix:** `frontend/src/test/setup.ts` now drops `[client-diagnostic]` warns globally (plain `console.warn` reassignment, survives clearAllMocks). If a similar `onUserConsoleLog`-pending teardown error appears from another test, the cause is the same class — a test flooding the console — silence that source in the global setup, not the test file. To triage a recurrence: `gh run view <run-id> --attempt 1 --log-failed` (the re-run overwrites `--log-failed`, so pass `--attempt 1`); grep the REAL error, not the benign `*_fetch_failed` diagnostic lines.
2. **`gh pr checks <n> --watch` exit code is UNRELIABLE** — it returned exit 0 while the `gates` job was actually `fail`. ALWAYS re-derive the real states with a plain `gh pr checks <n>` before crossing the merge (verify-the-critic; the irreversible step is human/check-gated, never trusted on a watch's exit code). See [[git-ff-main-sync]] (an interrupted agent's worktree can also be on a STALE base — `git fetch` + rebase onto `origin/main` before merging; split an AccountPage-style conflict by keeping the newer surface's structure and re-applying only the slice's semantic edits).
