When landing worktree work on `main` via fast-forward, keep the **local** `main` ref in sync with `origin/main` in the same step — don't `git push origin HEAD:main` from the worktree and stop there.

**Why:** pushing `HEAD:main` from a worktree updates the *remote* `main` but NOT the local `main` branch ref. On 2026-06-08 this left the primary checkout `${PROJECT:coachai|backslash}` **43 commits behind** `origin/main`, so another agent reading that checkout saw stale pre-consolidation code (a deleted `CallReviewView.tsx` still "present", `TeamInsightsPage` still wired to v1) and concluded a genuinely-orphaned analytics event was still live. Any fresh worktree spun off the stale local `main` inherits the same old code, and the user sees old code in their primary checkout.

**How to apply:** right after FF-ing `origin/main` from a worktree, also fast-forward the local main checkout —
`git -C "${PROJECT:coachai|backslash}" fetch origin main && git -C "${PROJECT:coachai|backslash}" merge --ff-only origin/main`
(verified safe: a `--ff-only` merge preserves uncommitted edits to files NOT in the incoming range — confirmed by checking `git diff --name-only <old>..origin/main -- <file>` first). Or land via the GitHub PR merge button, which keeps both refs reconciled. Either way, verify `git -C "${PROJECT:coachai|backslash}" rev-list --count HEAD..origin/main` = 0. Caveat: don't FF the main checkout out from under an agent that's actively working in it — coordinate/stop it first. Relates to [[ux-ui-redesign-audit]].

**Before `git checkout main` to sync, VERIFY the shared checkout is actually ON `main` AND clean** (`git -C <checkout> branch --show-current` == main, `git status --short` empty) — a blind `checkout main` switches whatever branch is there. 2026-07-08: the DIALER main checkout `${PROJECT:auxara-dialer|backslash}` was on ANOTHER session's branch `codex/s13-doc-drift-closure` with 41 uncommitted files; my blind `git checkout main` switched that session's HEAD onto `main` (carrying their WIP over), and the follow-on `merge --ff-only origin/main` aborted on the dirty tree. **No ref was corrupted** (both branches sat at the same commit `cfeefde`, so `git checkout codex/s13-doc-drift-closure` restored their HEAD + all 41 files cleanly), but I disturbed a live checkout. Rule: if the shared main checkout is on a FOREIGN branch or dirty, **NEVER `git checkout main`** (it switches that session's HEAD). BUT you CAN still sync the local `main` REF safely, because `main` is not the checked-out branch: **`git -C <checkout> fetch origin && git -C <checkout> branch -f main origin/main`** moves ONLY the `main` pointer — it does not touch HEAD or the working tree, so the foreign session (its branch + uncommitted files) is completely undisturbed. (2026-07-08: after backing out the bad `checkout main`, `git branch -f main origin/main` synced the dialer's local `main` from `cfeefde` → `3719b1a` with the `codex/s13-doc-drift-closure` session's 41 dirty files fully intact — verified.) `git branch -f <b> <target>` REFUSES if `<b>` is the current HEAD, so it can never clobber the checked-out branch. Prefer this over leaving main stale. Only if you can't even do that (main IS the occupied checked-out branch), leave it stale and rely on `origin/main` (post-`git fetch`) as the base for new worktrees — a stale local `main` ref is harmless as long as worktrees always cut from `origin/main`. Relates to [[worktree-stale-shared-dist-falsered]].

**Review/dispatch briefs must NEVER name a bare `git diff origin/main..HEAD` as the review surface — it reads against a possibly-stale LOCAL `origin/main` and injects phantom deletions.** 2026-07-08 (F-1 slice, PR #177): the brief told the adversarial + source-to-screen auditors to diff `origin/main..HEAD`, but the branch base predated merged sibling slices (dialpad), so the stale local `origin/main` was NOT an ancestor of HEAD → the two-dot diff showed **688 lines of phantom frontend deletions** (AuxaraConnectPanel etc.) that belonged to already-merged work, not the slice. Both auditors independently re-derived the real surface (`git show HEAD` = 11 files) and flagged the brief. An auditor trusting the brief's diff verbatim would have mis-attributed the deletions to the slice. **Rule for every reviewer/implementer brief:** always `git fetch origin` first, then specify the review diff as `git show HEAD` (single-commit slice) or `git diff $(git merge-base origin/main HEAD)..HEAD` (multi-commit) — never a bare `origin/main..HEAD` against a local ref that may lag or diverge. Same fix also means: a CONFLICTING PR after sibling merges → rebase onto the freshly-fetched `origin/main` before review/merge (the doc-row conflict F-1 hit was a clean 3-way merge, code auto-merged). Generalizes to ANY project → candidate for the global reviewer-brief template + `bootstrap-orchestrator`. Relates to [[worktree-stale-shared-dist-falsered]].

**Run the source-of-truth gate ladder LOCALLY before every FF-push to main — FF-push bypasses the PR CI gate.** The `.github/workflows/ui-source-of-truth-gates.yml` gate (check:ui, check:ui-continuity, lint:typography, **test:doc-code-drift**) runs on `pull_request` + `push:main`, but a direct `git push origin HEAD:main` from a worktree lands the commit BEFORE CI can block it — CI then just goes red on an already-shipped commit. On 2026-06-09 the g5 owner-cockpit FF-push landed `OwnerBusinessHealthOverview.tsx` (a new `dashboard/tabs/*` authority consumer — that whole folder is auto-discovered by the drift gate) without classifying it in `docs/app-plan/v2-authority-source-inventory.json` → **main sat red on `doc-code-drift`** until g6 caught it. This is the SECOND occurrence of the class (Slice 2.4 = 3 unclassified rep-dashboard consumers). Rule: any new `frontend/src/pages/*.tsx`, `dashboard/tabs/*.tsx`, `dashboard/myCoaching/*.tsx`, or `callReview/v2/*` file is an auto-discovered authority consumer → add it to `frontendAuthorityConsumers` (`"migrate"`, like its siblings) in the same change, and run `npm run test:doc-code-drift` (plus `check:ui`/`check:ui-continuity`/`lint:typography`) locally before the FF-push.
