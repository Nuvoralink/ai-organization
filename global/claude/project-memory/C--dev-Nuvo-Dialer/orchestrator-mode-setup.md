**Loop discipline wired (Amin, 2026-06-13; rule: `rules/loop-discipline.md`, always-on both vendors, PR #40):** bounded execution loops are now a STANDARD orchestration tool — Amin: "anything that can benefit from loops do it, but with tight guardrails… no loop ever falls into infinite looping." Every loop declares a CONTRACT up front: a *measurable* exit criterion + a hard iteration cap (default 3–5) + monotonic-progress-or-stop + a budget bound. Guardrails: no-oscillation (A→B→A halts), dedup-against-all-seen (find-until-dry exits on K≈2 dry rounds), don't-chase-a-moving-target (re-baseline once), **verify-the-critic** (a reviewer/gate/sub-agent "done/clean/merge" is a *lead, not proof* — anchored to the 2026-06-13 PR #39 buy-cart-footer false-premise miss where a reviewer cleared a real blocker after mis-resolving the PR number + diffing only vs `main`), escalate-don't-spin (escalation = a *successful* termination). Cadence = auto-converge-within-cap (default, crisp criteria) vs pause-per-iteration (fuzzy/expensive/irreversible). **The merge (the irreversible step) is HUMAN-GATED** (PR #41, the load-bearing principle): a loop may auto-iterate *inside* the cap but never crosses the one-way step (merge / publish / prod-write / delete / deploy) on a critic's *unverified* "clean" — the human checks the sensor against the actual code before the merge, and that gate is what makes autonomous iteration safe vs "auto-ship whatever the critic rubber-stamped." The critic fails **two** ways, both caught by re-deriving the claim from the actual diff before merging: *confidently-wrong* (the PR #39 review cleared a stale footer on a misidentified PR) AND *incomplete* (the same review missed 5 of 7 inline-copy literals).
