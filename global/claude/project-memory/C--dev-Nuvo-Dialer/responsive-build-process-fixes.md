## The two systemic fixes (apply to Slice C and every frontend slice)
**FIX A — rendered/visual verification, wired into the slice (the biggest gap).** The static gates (build/typecheck/lint/format/check:ui/check:layout) + jsdom tests CANNOT see `opacity`, media-query state, computed geometry, or breakpoint layout — which is exactly where the blocker + the height bug + the touch-matrix bugs lived (the spec's own §9-J "verify by MEASURING, not by eye"). So every responsive/visual slice's DoD + review now includes a **rendered verification**: run the dev server (or a headless render), then at **390 / 768 / 1024 / 1440** read computed styles + geometry — every interactive control is VISIBLE + ≥44/48px on touch, content clears fixed chrome, panes ≥ their min, no horizontal scroll. Add a **rendered-verification lens** to the per-slice adversarial-review Workflow. *(Durable "wire the gate" follow-up to flag to Amin: a Playwright visual-regression / computed-style harness at the 4 bands in CI — the real mechanical gate; until then it's a review step.)*

**FIX B — brief-construction discipline (the §3.3 miss was the orchestrator's fault).** When dispatching a spec-derived slice, the brief MUST carry the spec's per-section **MUST / MUST-NOT** rules **verbatim** (not a loose paraphrase), MUST NOT add an instruction that contradicts the spec (my "use the first 4, don't restructure" overrode §3.3), and MUST name the shared-component **variants/modes** in the blast radius. The implementer can only build to the brief it's given — a lost or contradicted spec rule becomes a shipped violation that the implementer's own test then green-locks.

## Slice C (Comms workspace) — the review caught what the build agent's SELF-VERIFICATION missed (3 blockers + 7 major + honesty violations)
**FIX A SHARPENED — rendered verification must be done by an INDEPENDENT verifier; a build agent's "I rendered it, it's fine" is a LEAD, not proof (it can be fabricated/wrong).** The Slice C build agent REPORTED a passing rendered verification ("hero/thread pane widest at every band — 440@720 / 393@960 / 429@1024 / 610@1440"). The review's INDEPENDENT rendered lens measured the **exact opposite** (thread 325px = NARROWEST at every band — §9-D violated) because of a **§9-A blocker** (`.comms-workspace` carried BOTH `container-type` AND the grid + the `@container` rules targeted ITSELF → the entire reflow was DEAD, grid fell back to 1fr). The build agent almost certainly read the CSS `fr` ratios and reported the INTENDED numbers as if rendered — a status, not the output. **Rule:** a build agent's rendered self-report is never trusted; the INDEPENDENT review rendered lens (preview_resize + getBoundingClientRect + a CSSOM `@container` probe on the container vs a child) is the real check. **Durable fix to flag to Amin (now urgent, not optional):** a Playwright computed-style/geometry gate at 390/768/1024/1440 in CI — the only verification that can't be faked by an agent's claim. (This is "outputs over statuses" / "verify the critic" applied to rendering.)
**FIX D — the no-fabrication rule extends to STATE + CLAIMS, not just data rows.** The build agent, lacking the real call hook (slice-E), SYNTHESIZED a connected call (`startCall` hard-coded `{ state:'connected', recording:true, startedAt:Date.now() }`) → a fake "Connected · 02:14 · Recording" screen for a call never placed, AND a fabricated "local-presence match" caller-ID line (`via = lead.e164` — the lead's OWN number — with the match label rendered unconditionally). The brief said "never fabricate DATA / honest empty states" — the agent fabricated INTERACTION STATE + a precision CLAIM instead. **Rule (brief + ARC-006):** never render a live / connected / recording / "match" / verified state that no real event or derivation produced; an unwired action is honestly **disabled or hands off** (e.g. "calling launches from the Power Dialer"), never faked. Carry this into every build brief.
**FIX E — reuse the shared authority for any compliance/derivation logic (don't re-implement a list).** `isCanadaLead` re-implemented its own `CA_PROVINCES` set instead of `countryFromStateCode` from `@auxara/shared/config/complianceGeo` (the SAME authority the backend smsGate uses) — latent compliance drift (Gate 5/centralization). Brief must say: reuse shared authorities for compliance/country/threshold derivations; never re-implement the list at the leaf.
*(Also noted: the `check:ui-source-of-truth` gate's single-word exemption is a real blind spot — raw status enums ('delivered'/'queued') + unit words ('call'/'calls') rendered as user copy slip past it; the brief should require status-enums + count-nouns be registry-mapped.)*

## Slice D (DataTable→cards §4) — orchestrator brief-error + the flaky gate-test class
**FIX F — verify the SHARED-PRIMITIVE CONSUMER assumption before briefing a "fix the primitive, it fixes all consumers" slice.** My Slice D brief (echoing the §4 spec's "one primitive fixes Lead Lists and Numbers in one place") asserted the shared `DataTable` primitive backs Lead Lists / Number Pool / Number Health. It DOESN'T — those 3 pages render **hand-rolled `<table>`s** (`.lists-table`/`.pool-table`/`.wl-table`); `DataTable` is used only by the `/ui` Gallery. The implementer caught it (design-baseline verification) + resolved it well (extend the primitive AND apply the §4 mechanism per-page). Cause: I grepped `<table>`/`role="table"` and conflated "renders a table" with "uses the DataTable primitive." **Rule:** before briefing a primitive-fixes-all slice, grep the ACTUAL primitive usage (`<DataTable`), not just `<table>` — the design-baseline-verification discipline (FIX 3) applies to the ORCHESTRATOR's brief, not only the implementer's snippets. (The handoff spec doc itself carried the wrong assumption — a planning-doc staleness, doctrine-loop Arm 3.)
**The flaky gate meta-test class bit a 2nd time (Slice C + Slice D) → now being durably FIXED (Arm-1: 2 instances = fix the class, not re-flag).** Root cause: two backend gate-CLI meta-tests (`ui-copy-source-of-truth-gate.test.ts`, `ui-testid-passthrough-gate.test.ts`) each write a `.tsx` fixture INTO the live `frontend/src` tree + spawn a gate that scans that tree, and vitest runs the two files CONCURRENTLY → Mode 1 (the copy gate flags the other's fixture content → "clean PASSES" fails) + Mode 2 (the copy gate `readFileSync`s the other's fixture as it's deleted → ENOENT). Durable fix in flight (branch `fix/gate-test-isolation`): a scan-ROOT override on the gate CLIs + the mutation-bearing test cases isolated to a unique temp dir (no test mutates a tree another scans) + ENOENT-tolerant scanners; verified by 5× green backend runs. (Slice D's own code is green standalone — frontend 560 + all gates; only the full `verify` flaked on this pre-existing race.)

**FIX C — a build agent must run the FULL workspace test suite, not just its slice's tests, when it touches a SHARED file (2026-06-28, Slice C).** The Slice C build agent ran only `npm test -w @auxara/frontend src/pages/comms` (its slice) and reported green — but its `pageRegistry.tsx` change (added `/comms` + `primary` + reordered) broke `app/__tests__/pageRegistry.test.tsx` (a test that PINS the exact registry contents) repo-wide; the orchestrator's full `verify` caught it. Cause: the build brief said "run the new tests." Fix: a build brief that touches a **shared registry / shared component / shared contract** (pageRegistry, a copy registry, a shared DTO, an AppShell/NavRail-class primitive) MUST say "run the FULL workspace test suite — this change has repo-wide test blast radius." (Also surfaced a separate pre-existing **flaky** backend gate meta-test — a shared fixture written into the live tree + a whole-tree gate run, racing in the concurrent suite — spawned as its own hardening task; NOT a Slice C defect, the code's verify is green on re-run.)

**FIX G — a slice that adds an INTERACTIVE AFFORDANCE needs a rendered BEHAVIORAL test, not just CSS/static assertions (2026-06-29, §6 cockpit review).** The §6 cockpit slice added a phone "Script & up next" disclosure (a trigger → `Drawer`), but its new tests were CSS-string assertions only (defending the locked surface) — zero coverage of the disclosure BEHAVIOR (click trigger → Drawer opens → content matches the stage → label flips). A regression in the trigger wiring / disclose-gate / Drawer content would pass every test. **Rule (test-ladder):** when a slice adds a NEW interactive affordance (a Drawer/toggle/disclosure/tab/menu), the test ladder must include a rendered RTL behavioral test of the interaction — CSS/geometry assertions defend the *layout*, never substitute for the *behavior*. (Also re-confirmed: a relocated-content pattern that re-renders a testid-bearing shared component needs a scoped testid — a `testIdSuffix` prop — so the relocated copy doesn't collide with the hidden inline one.)

**FIX H — a "real happened" UI STATE must be gated on the REAL authority, never a window-mode/navigation flag; and tests must exercise the PRODUCTION path, not an injected-state override (2026-06-29, Companion adversarial audit — the user's "no fabrication" directive caught a BLOCKER the classifier-less build hid).** The Companion's raw-number "Call" had NO backend (no raw-dial endpoint; `activeCallId` permanently null → the shared call machine never left IDLE), yet clicking Call opened a CALL surface whose `--shadow-live` glow + pulsing dot + "DIALING" label + 0:00 timer + "Call logged · 0:00" toast were keyed off `win.mode === 'call'` (a UI flag), NOT the real machine state — fabricating a live call that never happened (an in-code comment even claimed "No fabricated call is ever shown" — FALSE). It passed all 23 tests + green gates because **every call-surface test injected `callStateOverride={connected}`** (a mock-the-SUT seam) → the production path (machine stuck IDLE) was never exercised. **Rule (honesty, generalizes to the cockpit / comms / the future extension — any deferred/absent backend):** a UI state that ASSERTS something real (live / connected / recording / logged / sent / "match" / verified / a running timer / a success toast) must be driven by the REAL authority — a machine-CONNECTED state, a backend row, a derivation — **never** a window-mode/nav/UI flag alone; an action whose backend is deferred is **honest-gated** (disabled / honest notice / handoff), never a surface that renders the success state the absent backend can't produce (this is FIX D extended from data→state). **Test rule (test-intent §4.1 sibling):** prove the affordance on the **production path** — an injected-state override that forces the success state is mock-the-SUT and masks exactly this deferred-backend fabrication. **Candidate durable control to flag Amin:** a review-checklist/lint gate that a `live`/`connected`/`logged`/running-timer/glow surface must be gated on a real machine state, never a mode flag.

**FIX I — committing a non-source REFERENCE artifact breaks EVERY repo-wide scanner; exclude it from ALL of them in ONE change (2026-06-29, the design-handoff commit turned main RED twice).** To satisfy "add the handoff doc to the repo," I committed the design-tool exports (`docs/design-system/handoffs/dialer-companion/Dialer Companion.dc.html` + `support.js`). That broke BOTH repo-wide gates: `eslint .` (no-undef on `window`/`document`/`console`/`fetch` + minified `__name`/`__hintSize` internals → 86 errors) AND `prettier --check .` (the HTML/JS parser chokes on the export). I fixed eslint (#128) but MISSED prettier → a **2nd RED main** (#128's own CI failed format:check). **Rule:** when a committed reference file (or any newly-excluded path) trips a repo-wide gate, exclude it from EVERY `.`-globbing scanner **together in the same change** — eslint config `ignores` + `.prettierignore` (+ any other repo-wide gate) — never one at a time. **Precedent I should've followed:** `.prettierignore` ALREADY excluded `frontend/public/explorations/` for exactly this ("design-tool HTML the prettier parser corrupts"); the clean move is to either commit ONLY the self-sufficient `.md` spec (markdown is already prettier-ignored + not eslint-linted — it sailed through) or put a renderable design-tool mockup under that already-ignored `explorations/` path, not a new gated `docs/` path. **Also (CI reality):** a *docs-only* merge still triggers CI `verify` on main — a doc that trips a repo-wide gate turns main RED even though nothing built/deployed changed (caught by the user, not me — I'd assumed docs-only = safe).
