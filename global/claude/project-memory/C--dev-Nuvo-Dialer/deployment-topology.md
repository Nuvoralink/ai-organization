**STAGING / PREVIEW WORKFLOW (set up 2026-06-28 — Amin's directive: "all previews merged into the `preview` branch").** There is a long-lived **`preview`** branch wired to a stable same-site staging URL so features are reviewable (logged-in) BEFORE they hit main/prod:
- **Staging URL = `https://staging.dialer.auxara.io`** → Vercel-assigned to the **`preview`** git branch (Valid Configuration). It's under `*.auxara.io` so it is **SAME-SITE** with the API (`dialer-api.auxara.io`) → the httpOnly cookie + double-submit CSRF (COOKIE_DOMAIN=`.auxara.io`, COOKIE_SAMESITE=`lax`) work. **A raw `*.vercel.app` preview URL is CROSS-SITE → the session cookie is never sent → login is impossible there; ALWAYS review via staging.dialer.auxara.io, never the vercel.app preview link.**
- **The workflow to preview a feature:** merge the feature branch INTO `preview` → push → Vercel auto-rebuilds staging → review at staging.dialer.auxara.io. `preview` is a STAGING AGGREGATOR — never merged to main; **main stays the real target via a normal PR.** (REPO_FILEMAP.md conflicts on every preview merge — both sides regenerate it; resolve by `npm run filemap` + `git add` + commit, trivial.)
- **Env that makes it work (configured 2026-06-28):** Vercel **Preview** env `VITE_API_URL=https://dialer-api.auxara.io` (scoped to the `preview` branch — set non-interactively via `vercel env add VITE_API_URL preview preview --value … --yes --force`; the git-branch positional is REQUIRED or the CLI blocks on the branch prompt). Railway `api` `ALLOWED_ORIGINS=https://dialer.auxara.io,https://staging.dialer.auxara.io` (both origins).
- **auxara.io DNS = Cloudflare** (nameservers jeremy/tara.ns.cloudflare.com) — third-party, NOT Vercel-managed, NOT MCP-accessible → any new subdomain/DNS record is **Amin's Cloudflare console step** (give exact records). `staging.dialer.auxara.io` is already set.
- **CLI footgun (cost me a prod scare 2026-06-28):** `vercel env rm VITE_API_URL preview --yes` removed VITE_API_URL from **ALL** environments (incl. Production), and the sandbox **blocks `vercel env add`'s interactive prompts** (returns a JSON `missing_arguments` hint). Use **`vercel env add NAME ENV [git-branch] --value "…" --yes --force`** (the `--value` flag + the git-branch positional = fully non-interactive). Never harvest the Vercel token (the safety classifier blocks credential-store scans — correctly).
