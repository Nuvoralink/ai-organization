**Settled 2026-07-01 (Amin-approved after a research pass; ADR + decision-log row OWED — write with the slice).** Pressure-tested "do we need a whole compliance page?" → NO. A standalone-page-per-settings-category is the "junk drawer" anti-pattern (research: ~70% of B2B churn is config frustration, not missing features).

**Decision — ONE Settings HUB:** route `/settings` with a **persistent LEFT settings sub-nav** (a settings-scoped sidebar, DISTINCT from the app NavRail) + a content pane per section; each section deep-linkable; **DATA-DRIVEN** (a `SETTINGS_SECTIONS` array → adding a section is a data entry — the scaling mechanism); role-scoped buckets **Account** (everyone) / **Workspace** (tenant admin: team, billing, numbers, integrations, 10DLC) / **Compliance** (admin write / Compliance-Viewer read); settings **search** + **progressive disclosure**; render ONLY real sections (no "coming soon" stubs — no-internal-narrative). NOT standalone pages, NOT tabs (tab-overload is a named failure mode), NOT one long scroll. Market-validated: Stripe (Personal/Account/Product) · Linear (Features/Admin/Teams) · GitHub (Security = a sidebar section with children) · Twilio (Trust Hub consolidates compliance) · Vercel (identical settings sub-nav at team vs project). Object pages link INWARD (a number's page → its 10DLC/recording setting) — "attach to the object AND collect in the hub."

**Compliance SECTION pattern (research-backed):** each Set-B capability = a row — a `Switch`/`Select` + a **plain "what it does / what happens if OFF" line** (the anti-Convoso rule; "opaque interdependent settings" is the #1 dialer-review complaint; NO hidden cross-effects). Turning OFF → a **risk-ack modal** with a **MANDATORY "I understand — I'm the liable caller" checkbox that keeps the Disable button DISABLED until ticked** (clickwrap) → a **persistent ⚠ "Disabled — you're liable" badge** on the row (state stays visible, not a one-time modal) + an honest `tenant_disabled` audit basis (ARC-004). An inline "recent changes" mini-log `{who·old→new·when}` + a link to the full **immutable audit log** (config vs audit-EVIDENCE = DISTINCT surfaces, cross-linked — the Compliance-Viewer's `BENCH-PRO-COMPLIANCE-AUDIT` surface). Set-A (STIR/SHAKEN, 10DLC, STOP, internal-DNC, US/CA destination lock) = a **terse "always on — automatic"** list, NOT toggles, NOT a status grid (no-plumbing). Advanced (per-state windows) behind "Show advanced." Kixie's **Block/Override mode** = literally our CMP-012 block/confirm/off (market-aligned).

**Scope (Amin's call):** first build = the hub SHELL + the Compliance section (CMP-020); other buckets slot in later. **Mockup-first** — building `feat/settings-hub-mock` (implementer). Backend owed POST-approval: a `ComplianceDisableAcknowledgment` append-only model + migration, `GET/PATCH /api/tenant/compliance-config` + `POST` disable-ack routes (the Set-B flags `callingHoursEnforced`/`dncScrubEnabled`/`recordingDisclosurePolicy`/`recordingEnabled` + the honest-`tenant_disabled` gate already exist).
