**`main` is NOT gated by CI, and cannot be on the current plan.** `.github/workflows/ci.yml` runs the right jobs — `verify` (build/lint/format:check/typecheck/test/gates:all), `docker-build`, `integration` — but `gh api repos/Nuvoralink/auxara-dialer/branches/main/protection` returns **403 "Upgrade to GitHub Pro or make this repository public to enable this feature"** (confirmed 2026-06-16). Branch protection / required status checks are unavailable for a **private repo on the free plan**, so `gh pr merge --auto` merges **immediately regardless of CI result** (PR #66 fast-forwarded in seconds; PR #65 had merged with 2 files failing `format:check`, leaving main's `verify` RED until #66 fixed it).

**Discipline until the plan changes — the merge gate is LOCAL, not CI:**
- ALWAYS run `npm run verify` (read the REAL exit code, not a piped one) + `npm run test:integration` for DB-touching changes BEFORE merging. Do NOT trust `--auto` to gate — it doesn't.
- This is the 2026-06-11 "ran `gates:all`, not full `verify`" lesson one layer up: CI runs `verify`, but can't *enforce* it.
- A stale local `node_modules` makes `verify`'s frontend build fail on a missing dep (e.g. `@telnyx/webrtc` after the S1.2-E merge) — `npm install` first when build can't resolve an import that's in package.json.

**Worktree-commit footgun (2026-06-28, bit TWICE on the nav-bleed-fix PR #112/#113):** when committing via an **isolated worktree off main** (the right move when the main checkout is dirty with another lane's WIP), the worktree has **no `node_modules`**, so you CANNOT run `verify` there → easy to merge unverified. PR #112 merged and CI went RED at `npm test`; the format-fix PR #113 ALSO went RED at `format:check`. **Rule:** before copying files into the worktree, run the checks in the **MAIN checkout** (it has `node_modules`): `prettier --check` on **EVERY changed file** (I ran it on 6 files but FORGOT the 7th — the test — twice), the **affected tests**, `check:ui`, `gate:doc-code-drift`. Then watch the post-merge CI run to GREEN (`gh run watch <id> --exit-status`) — never merge-and-forget.

**Background sub-agents DIE on host-process exit (no resume); long delegated work → Workflow (resumable) or foreground (2026-06-28, Slice B).** A `run_in_background: true` Agent died mid-build when the Claude Code process exited — its in-process state was lost (the notification said "did not complete"). BUT its file edits had landed on disk (uncommitted in the worktree), so the work survived + was recoverable. Lessons: (1) for a long delegated build, prefer the **Workflow** runner (resumable via `resumeFromRunId`) or a **foreground** Agent (completes in-turn); (2) when a background agent finishes, VERIFY its worktree (it never ran its own checks) — don't trust "done"; (3) the **multi-lens adversarial review Workflow** (4 parallel lenses: doneness / responsive-correctness / token-copy-a11y / test-bite) caught a real **blocker + IA violation the green gates + the slice's own test had green-LOCKED** — the gates are necessary-not-sufficient; the exhaustive review is where shell-level (high-blast-radius) regressions actually get caught.

**Stale-base on a long slice branch → rebase-before-merge + the async-mergeability race (2026-06-28, Slice B PR #117).** A slice branch cut off main goes STALE while another lane merges (s13-sms landed during the long Slice B build+review+fix). `gh pr merge` then fails "resolve the merge conflicts locally." Fix: in the worktree `git fetch origin && git rebase origin/main`, resolve (here only the generated `REPO_FILEMAP.md` — `git checkout --ours` then regenerate `node scripts/generate-repo-filemap.mjs` + `git commit --amend`), re-run full `verify`, `git push --force-with-lease`. GOTCHA: right after a force-push, GitHub recomputes mergeability ASYNCHRONOUSLY — `gh pr merge` run immediately acts on the STALE "CONFLICTING" status and fails AGAIN even though it's now clean. Check `gh pr view <n> --json mergeable,headRefOid` (want `MERGEABLE` + head == your local SHA) before retrying; `--admin` merges past an `UNSTABLE` (CI-pending) state on the un-gated main. AND: after merging, watch the CI run whose `headSha` == your merge commit — `gh run list --limit 1` can return the PRIOR lane's run (a false green).

**Behavior-change → update its GUARD TEST in the SAME change (Gate 4 blast radius).** The nav-bleed fix changed `NavRail.css` from opaque-`--surface-solid` to transparent-rest + frosted-drawer; `NavRail.test.tsx` had a guard test ASSERTING the old solid bg (a deliberate killer-mutation guard) → it red-lit. When changing locked/guarded behavior, `grep` the tests for assertions on the OLD behavior and flip them in the same PR — a CSS change has a test blast radius.
