Auxara Dialer Sprint 1.3 placeholder authority retirement and exhaustion semantics.

- When backend/shared authority exists for a built live surface, retire the old frontend placeholder in the same source-to-screen slice. For the softphone/companion/comms surfaces, retired live placeholders are `PLACEHOLDER_SCRIPT_SECTIONS`, `PLACEHOLDER_BATTLECARDS`, and `PLACEHOLDER_SMS_ELIGIBILITY`; `gate:authority-placeholders` now prevents them from returning under `frontend/src/pages/{softphone,companion,comms}`.
- Teleprompter script now reads `GET /api/teleprompter-configs` through `frontend/src/lib/api.ts` and renders in `CallCard.Script`; battlecards now read `GET /api/battlecard-triggers` and render in `CallCard.BattlecardStrip`; Companion SMS entitlement reads `GET /api/tendlc/brand`, and raw-number text sends through `api.conversations.sendToNumber` into a contactless conversation.
- Teleprompter reads for an individual-owned list must use the same list-access authority as dialing (`canDialList`), not a team-only check; otherwise personal lists can dial but cannot read their script config.
- DLR-010 exhaustion is calculated by backend queue authorities, not by the frontend or a user toggle. Solo dialing uses `dialerEngine.next()`/`dial()`; shared team runs use `dialRuns.reserveNextDispatch()` and distinguish `waiting` from `exhausted`. Temporary blockers such as active dispatches, defer, recycle gap, or daily-attempt cap are waiting, not exhausted. The policy knobs are list fields `recycle_min_gap_minutes` and `max_attempts_per_lead_per_day`; there is no “disable exhaustion” switch.
- Workflow auditors must explicitly ask “how does the user do this?” and verify create/assign, discover, act, recover, and later change paths, not just API/schema existence.
