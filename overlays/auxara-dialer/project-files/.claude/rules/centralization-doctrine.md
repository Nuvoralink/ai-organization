# Centralization Doctrine — One Source of Truth Per Domain

Purpose: prevent the most-expensive class of architecture drift in a multi-tenant, multi-surface SaaS — the kind where the same concept gets restated in 30 different files, each version slightly different, and nobody notices until prod data is inconsistent or a tenant sees mismatched copy.

The rule: **no individual file holds domain truth.** Every domain has ONE central registry. Every consumer reads from that registry. Changing the truth means changing one row, not 30 files.

This rule applies to every task that touches code, prompts, docs, or content. The CI gate `npm run gate:doc-code-drift` enforces structural pieces of it.

## 2. Forbidden patterns

These are bugs even if they compile and tests pass:

- ❌ Inline string literal for user-facing copy: `<Button>Save</Button>`. **Use** `<Button>{copy.softphone.actions.save}</Button>`.
- ❌ Inline hex color: `className="bg-[#3B82F6]"`. **Use** the token: `className="bg-brand"` (mapped through tailwind config).
- ❌ Inline font: `style={{ fontFamily: 'Inter' }}`. **Use** the token: typography.body.
- ❌ Magic numeric: `if (daily_count > 75)`. **Use** `if (daily_count > thresholds.numbers.dailyCapDefault)`.
- ❌ Hardcoded permission string: `if (user.role === 'manager')`. **Use** `if (hasPermission(user, PermissionKey.MONITORING_BARGE, scope))`.
- ❌ Hardcoded API URL: `axios.get('/api/calls/' + id)`. **Use** `apiClient.calls.get(id)` (which routes through `shared/contracts/endpoints.ts`).
- ❌ Hardcoded event name: `track('dial_initiated')`. **Use** `track(Events.dialInitiated, payload)`.
- ❌ Hardcoded compliance reason string: `audit.write({ reason: 'calling hours violation' })`. **Use** `audit.write({ reason: ComplianceReason.CALLING_HOURS_VIOLATION })`.
- ❌ Hardcoded role name in test selector: `data-testid="manager-only-button"`. **Use** stable role-agnostic selector + RBAC test asserts visibility.
- ❌ Inline regex for normalization. **Use** the central normalizer (`shared/normalize/phone.ts`, `tz.ts`, `email.ts`).
- ❌ DTO shape redefined in two places. **Use** the single shared contract.
- ❌ Tailwind config diverging from `foundations.ts`. **Generate** Tailwind from foundations; never hand-edit Tailwind tokens.
- ❌ **Any raw design literal at the leaf** — `oklch(…)` / `rgb(…)` / a hex, a raw `16px` / `1.5rem`, a hand-written `box-shadow` / `cubic-bezier(…)`, a raw `linear-gradient(…)`, a font-name, a z-index number — anywhere under `frontend/src` **except** the token source (`design-system/tokens/*.css`). **Use** the semantic token (`var(--…)` or `foundations.*`). **If no token fits, add it at the source first** — the right primitive ramp / scale step → a semantic token — then reference it. Never inline a one-off "just this once." The `check:ui-guardrails` gate **fails the build** on this (mirrors the user-level rule "Tokens & scales — extend the source, never inline a raw value at the leaf").
- ❌ **A page that owns scroll/height** — `height: 100vh/svh/dvh`, `overflow: auto/scroll`, or `position: fixed` for layout in page/feature code. **Use** `AppShell` + `ScrollArea` — the shell owns the one scroll container (`docs/design-system/layout-and-ia.md` §1). The `check:layout` gate flags this.
- ❌ **An ad-hoc hand-rolled page header** — a `*__header` / `*__topbar` rule inventing its own surface treatment (a fill, a border recipe, its own blur) instead of referencing the one source. **Use** the ONE shared `.app-header` surface (`frontend/src/design-system/app-header.css` — a FROST PANE: transparent + backdrop-blur + sticky; the ambient flows through): the `PageHeader` primitive composes it, a rich page header co-applies `app-header` in JSX. Never re-declare a header surface per page, and never re-add an opaque fill to `.app-header` itself (the "solid bar" slab covered the ambient on every page; removed 2026-07-06 per user approval). The `check:header-surface` gate flags the ad-hoc class.
- ❌ **Info-dumping** — a wall of equal-weight fields in one card. **Use** the tiered model (Tier 1 visible / Tier 2 demoted / Tier 3 disclosed) + the card-vs-sections-vs-tabs-vs-disclosure rubric (`docs/design-system/layout-and-ia.md` §2).
- ❌ **Per-page IA reinvention** — the same object (number / lead / call) laid out differently page-to-page, or ad-hoc tabs/sections. **Use** one shared composite (`<NumberDetail>`, `<LeadCard>`): same object → same structure everywhere.

## 3. How to add a new central registry

When a new domain emerges (e.g. we add "battlecard categories" as a concept):

1. Decide: where does the truth live? (`shared/taxonomy/`, `shared/contracts/`, `shared/copy/`, `frontend/src/design-system/`, etc.)
2. Add the registry file in that location with the canonical shape (enum / DTO / map / etc.).
3. Add a row to §1 above (this rule's table).
4. Add a row to `docs/app-plan/assurance/source-of-truth-map.md` §"Authority inventory".
5. Add a row to `docs/app-plan/product/27-glossary-taxonomy.md` if it's a user/agent-facing taxonomy.
6. Update the relevant Cursor / Codex / Claude rule files if the registry has additional discipline.
7. Update existing consumers to source from the new registry (do not leave duplicate truth in two places).
8. Add a regression test that catches a future "inline literal" attempt for this domain.

## 4. How to change a central registry value

Changing a row in a central registry is a high-blast-radius change. Procedure:

1. Read every consumer per `docs/ARCHITECTURE_BLAST_RADIUS.md`.
2. Update the registry row.
3. Update consumers that derive UX/behavior from the value (e.g. a default daily cap change requires updating tenant onboarding seed + tests).
4. Run `npm run gates:all` — must pass.
5. Update the journey doc if the change taught a lesson about why the registry mattered.

## 5. CI gates (when scaffolds exist)

- `npm run gate:doc-code-drift` checks: every authority surface in `assurance/source-of-truth-map.md` resolves to a real file; every claimed central registry path exists; every glossary ID resolves.
- `npm run gate:doc-registry-refs` (`scripts/check-doc-registry-refs.mjs`, in `gates:all`; added 2026-07-07) checks the doc-prose SIBLING of the above: a LIVING authority doc (`docs/**`, `frontend/docs/**`, `.claude/rules/**` — the dated `docs/agent-prompts/` brief archive is excluded) must not name a `COPY.<surface>.<path>` key that no longer resolves. It AST-builds the real `COPY` key tree from `shared/src/copy/*` (index aggregation → per-surface consts, incl. shorthand; no build needed) and fails on any unresolved `COPY.*` reference — the class `gate:doc-code-drift` misses (it resolves registry PATHS, not the KEYS a doc cites). Origin: PR #192 shipped `FRONTEND_BLAST_RADIUS.md` still citing the deleted `COPY.workspace.theme`, caught only by the adversarial reviewer. History-tolerant, scoped to the ref's own CLAUSE (a removal verb in a different table-cell/sentence/parenthetical can't shadow a live ref sharing a dense line): a ref whose clause carries a removal/past-tense word (removed/deleted/renamed/…) or a line carrying a `doc-registry-ok` marker is skipped; a spread-contributed key is never false-flagged (OPEN guard). Scope is deliberately `COPY.*` only (deterministic; fuzzy taxonomy-const-name prose is NOT scanned — it false-positives). Meta-test: `backend/src/__tests__/doc-registry-refs-gate.test.ts`.
- `npm run gate:endpoint-wiring` (`scripts/check-endpoint-wiring.mjs`, in `gates:all`; added 2026-07-08, NFR-012) checks the ARC-008 endpoint registry's DELIVERY side: every internal (non-`external`, non-`/api/webhooks/`) key in `shared/src/contracts/endpoints.ts` — registry entries AND `PATH_SUFFIXES` fragments — has a symbol-resolved shared `API_ENDPOINTS.<key>` reference under `frontend/src`, or an explicit `PENDING_WIRING` row with `{ reason, owner, addedAt, decision }` (`addedAt` is a real ISO `YYYY-MM-DD` date). Fails on silently-unwired endpoints, stale/dead/invalid deferrals, unsupported registry AST members that could hide keys, and backend route mounts that statically reconstruct a full canonical path instead of mounting its exact key. Comments, strings, tests, backend-only refs, and locally shadowed `API_ENDPOINTS` objects cannot certify wiring. Deeper parity — an api.ts method no page calls, DTO-field production↔consumption, nav/role reachability, or dynamic helper-built mounts — is the `functionality-parity-auditor`'s lens; `PENDING_WIRING` rows are dated deferrals that auditor re-triages, never exemptions. Meta-test: `backend/src/__tests__/endpoint-wiring-gate.test.ts`.
- `npm run gate:rules-wiring` checks the agent-rules loader wiring (the single-source guard, added 2026-07-02): every `@.claude/rules/*.md` reference in `CLAUDE.md` resolves; every `.claude/rules/*.md` path in `AGENTS.md` resolves; every file in `.claude/rules/` is discoverable from `AGENTS.md` (Codex's only discovery surface); and the retired `.codex/rules/` mirror has not silently returned. Replaces mirror-sync vigilance with a mechanical gate.
- `npm run gate:test-intent` checks: every test's `Proves:` IDs resolve in the PRD or competitive benchmarks (which themselves are central registries).
- `npm run check:ui-guardrails` (run via `check:ui`) checks: no raw design literal — hex/oklch/rgb, px/rem, shadow, easing, gradient, font-name, z-index, duration — outside the token source (`frontend/src/design-system/tokens/*.css`); no Tailwind drift from `foundations.ts`; no raw `axios` import in a component.
- `npm run check:ui-source-of-truth` (run via `check:ui`) checks: no inline user-facing COPY in `frontend/src` components — JSX text, the `aria-label`/`placeholder`/`title`/`alt` attributes, multi-word phrase literals (helper messages / reject reasons / basis lines), and capitalized default-prop values must all be sourced from `shared/src/copy/*` (`{COPY.<surface>.<key>}`; `fill()` for interpolation). ## 6. Migration / adoption

When old code with hardcoded values is touched:

- Touching the file → required to migrate that file's hardcoded values to the central registry in the same PR.
- Adding a new feature in a file with existing hardcoded values → also migrate (do not perpetuate).
- Pure refactor PRs that only migrate hardcoded values to registry are welcomed.

## 7. The point

In CoachAi, the most-expensive class of refactor was "we have to update this copy in 23 places and we'll definitely miss one." Centralization prevents this from being possible. In the dialer — where role × permission × scope × tenant config × compliance gate × disposition × event × copy can multiply into thousands of cells — the centralization doctrine is not optional. It's the only way the architecture stays maintainable past 5 paying tenants.

A junior agent reading this rule should walk away with: "I don't write user-facing strings in components. I don't put hex colors in CSS. I don't compare role names with `===`. I look for the central registry first."
