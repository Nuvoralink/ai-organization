# Never Reactive — Dialer Adapter

**The universal `never-reactive` rule governs in full** (always-on at user level; Codex twin in `~/.codex/AGENTS.md`). This adapter does not restate its ladder — it only binds it to the dialer's surfaces and records the founding anchor.

## Dialer bindings

- A visible surface's structural plan is a **flow map + state inventory grounded in primary provider
  docs** (Telnyx first — it is the mechanic our backend actually calls; competitor help docs are the UX
  layer). The mock is built from the validated map, never before it (composes mockup-first +
  `frontend-design-director`; the map travels with the design handoff).
- Dispatch briefs carry the inferred intent + the map per the self-contained-brief standard
  (AGENTS.md §Execution); a sub-agent that finds the brief's intent contradicted by the authorities
  escalates, never literal-executes.
- A founder correction on any mock / surface / copy is a CLASS: extract the rule, sweep every state of
  every mock in the set for it, and capture it (rule or memory) the same turn.

## Founding anchor (2026-08-05, THIS repo — the 10DLC session)

A 10DLC dashboard was mocked as status-primitives from a research summary: the primary Telnyx docs
were unread, the flow unmapped, and the flow's third stage (number↔campaign attachment) entirely
absent from the design. "Why is Canada shown here?" was answered with a row-delete instead of the
class rule (an always-true state carries zero information — never render it). The founder had to
order "map out the full flow chart, make sure you have information of every stage, then build it" and
spell out the guided/adaptive intent piece by piece — every one of those steers was inferable from
his first question.

*Fail-state:* a dialer agent point-patched a steer, built a surface before its grounded flow map
existed, or dispatched work whose brief carried the task but not the intent.
